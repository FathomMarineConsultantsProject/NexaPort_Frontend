# Memory-only requisition intake

The selected PDF or XLSX is passed to a dedicated Web Worker and read only in memory. PDF.js text extraction, OCR fallback, and XLSX parsing return allowlisted requisition fields, items, warnings, and source page or cell references. The worker is terminated after success, failure, or cancellation. Application references to the File are released when the selection handler finishes; JavaScript garbage collection does not guarantee immediate memory erasure.

The user reviews the extracted data in the current page and explicitly selects **Save Requisition**. The backend accepts only structured JSON. It writes an audit row required by the existing item and warning foreign keys with a generic label, synthetic extraction ID hash, zero byte size, and null object key. The audit row contains no original filename, source hash, binary, base64, or full document text. A failed save leaves the structured result in page memory for **Retry Save**; refresh or close discards unsaved work. Saved details and items reload from PostgreSQL. The original cannot be previewed or re-extracted after the File reference is released; select it again when needed.

New intake does not open IndexedDB, localStorage, sessionStorage, Cache Storage, or OPFS to store original documents. A scoped **Remove old local document copies** control deletes only the legacy `nexaport-local-requisition-files` IndexedDB database after the user confirms and no unsaved extraction is present. It does not touch unrelated browser storage. Historical S3 source records are retained. Generated supplier RFQ PDFs continue to use private object storage.

The binary source upload route returns HTTP 410. New structured saves require the existing browser metadata schema from migration 012 because the current foreign keys still target `procurement_requisition_source_documents`. Migration 013 is not required for the new flow: it never uses the source file hash. Existing historical data and any hosted migration state must be reviewed separately before deployment. Local tests use only a disposable PostgreSQL database and `VITE_API_MODE=local`.

The isolated browser runner `tmp/intake-browser-retry.mjs` checks the CSL 40-item extraction, explicit save, in-memory retry, Chrome network and storage, database metadata, refresh persistence, supplier RFQ confidentiality, Excel extraction, and scoped legacy purge. `tmp/intake-retry-regression.mjs` checks idempotency, concurrency, authorization, correction preservation, historical coexistence, and transactional rollback.
